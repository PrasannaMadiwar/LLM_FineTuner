# Deploying to Render

This repository includes `render.yaml` for three Docker services:

- `llm-finetuner-api`: public FastAPI service.
- `llm-finetuner-web`: public Next.js application.
- `llm-finetuner-worker`: Celery worker for asynchronous training jobs.

## Deploy

1. Push this repository to GitHub.
2. In Render, select **New > Blueprint** and select the repository.
3. Review the three services defined in `render.yaml`.
4. Enter every value Render prompts for. Use the values from your local `.env`; do not commit that file.
5. Create the Blueprint and wait for the API deployment to complete its database migrations.

The Blueprint assumes the default Render URLs:

- `https://llm-finetuner-api.onrender.com`
- `https://llm-finetuner-web.onrender.com`

If Render requires different service names or you add a custom domain, update both `NEXT_PUBLIC_API_BASE_URL` on the web service and `API_CORS_ORIGINS` on the API service, then redeploy the web service.

## Required values

Set these values in Render when prompted:

- `DATABASE_URL`: Supabase PostgreSQL URL using the `postgresql+asyncpg://` scheme.
- `REDIS_URL`: hosted Redis URL.
- `GPU_AGENT_TOKEN`: a long random token; enter the same value for the API and worker.
- `OPENAI_API_KEY`: required for semantic mapping features.
- `RUNPOD_API_KEY` and `RUNPOD_TEMPLATE_ID`: required for RunPod training.

Enter the same `DATABASE_URL`, `REDIS_URL`, `GPU_AGENT_TOKEN`, OpenAI key, and RunPod values for the API and worker when Render prompts for each service.

`JWT_SECRET_KEY` is generated by Render for the API. Do not replace it with a development value.

## Plans and storage

Render's free plan supports the API and web services, but background workers require a paid plan. The Blueprint uses Render's smallest worker plan for `llm-finetuner-worker`; remove that service only if asynchronous training is intentionally unavailable.

Free Render web services spin down after idle time and use ephemeral filesystems. Uploaded datasets at `/app/storage` are lost after a restart or redeploy. Use object storage or a paid persistent disk before relying on uploads in production.
